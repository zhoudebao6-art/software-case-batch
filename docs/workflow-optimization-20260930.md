# 2026-09-30 成品优先流程落地记录

用户目标：减少额度消耗，加快每案一个 Word 和一个视频的交付；保留完整网页框架供以后完善。本次不重开旧批次，不恢复定时监督，不改变其他项目与拟名称服务。

## 已实施的执行变化

| 环节 | 新批次行为 |
| --- | --- |
| 建设范围 | 保留完整导航、模块标题与路由；完成两个体现案件系统形态的业务操作页面，重视布局/功能/内容，其他模块内容可空 |
| 计算与图表 | 一套可复现输入实际计算；结果供图文及页面必要业务字段使用，页面不以图表为主体；图可离线生成后直接插 Word |
| 模型 | 建设 gpt-6.1-sol/high，返修 gpt-6.1-sol/ultra；普通独立检查 gpt-6-sol/ultra；明确加急 Astra low |
| 并发 | 建设/普通返修 8 槽；普通独立检查 3 共享槽；录制默认 2 槽（受内存准入保护），受控证据 1 槽 |
| 录制 | 建设时准备两个页面及 schema 2 计划，父执行器固定程序录制，无单独视频模型调用 |
| 返修 | 文档专用图/正文/证据截图变化不自动重录；实际录制代码、数据、路由、操作和版本变化才重录 |
| 图表检查 | 新流程逐图核对 PNG、数据、说明与 Word 正常尺寸证据，不强制网页同图；网页/视频仍单独检查 |
| 提示词 | 新流程使用独立简化的阶段提示词，去掉完整系统建设、全部业务路由测试等旧要求 |
| 状态文件 | 批次状态只存当前阶段与摘要；详细调用、证据、计数仍完整保留在每案 state |
| 交付后 | 原材料、源码、图表、数据和日志留在工作区；按身份核验回收专属闲置后台 |

`config.json` 的新默认为 `deliverable-first-v1`，批次登记后冻结，旧 legacy/efficient-v1 不自动迁移。新批次还冻结录制并发配置：默认两路录制，doctor 先检查 4096 MB 基线加每个额外槽 2048 MB 预留；内存不足只降低本机新批次录制并发，不降低模型或质量。录制程序复用一次真实浏览器会话，避免重复预热启动。每案状态和原审查报告不改为通过，也不把旧通过用于新文件。

这次减少消耗主要靠缩小制作范围、一次计算多处使用、程序录制、按影响修复，以及不重复生成未变产物；不承诺固定节省比例，也不以减少必要数据/图文真实性检查换取提速。
