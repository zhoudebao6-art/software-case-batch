# 在另一台 Windows 电脑使用

此版本支持 Windows 10/11、PowerShell 5.1 或 7。尚未验证 macOS/Linux 的实际制作链路。仓库部署的是制作程序，不是把原电脑所有在制案件搬走；推荐两台电脑各自承接不同的已确认批次。

## 1. 准备工具和账号

安装 Git、Python 3.11+、Node.js 20+、LibreOffice、FFmpeg（含 ffprobe）、Poppler（含 pdftoppm）和 Codex。Codex CLI 需在新电脑单独登录，具备配置中的建设/返修/验收模型权限。不要从原电脑复制 auth.json、令牌、浏览器用户目录或账号数据库。

Codex 桌面自带的 Python、Node 模块和 Poppler 可以被安装器自动发现。LibreOffice/FFmpeg 或其他不在 PATH 的工具，须在新电脑 `config.json.runtime` 填写真实可执行文件路径。工具缺失会被 doctor 列出；安装器不放宽系统安全设置。原项目的 `D:`/`E:` 盘符和用户名均不是要求。

## 2. 克隆与安装

私有仓库需要该 GitHub 账号或获授权的协作者访问。先用 GitHub CLI `gh auth login` 或 Git 的正常登录方式授权，然后在选定目录执行：

```powershell
git clone https://github.com/zhoudebao6-art/software-case-batch.git
cd software-case-batch
.\scripts\setup.ps1 -InstallDependencies -InstallSkill
```

`-InstallDependencies` 只安装此项目 `.venv` 中的 Python 包、本目录 Node 模块及匹配版本 Chromium，不全局安装/升级 Python 包。Playwright 包与浏览器版本相互匹配，安装或升级包后应同步安装浏览器，见 [Playwright 浏览器说明](https://playwright.dev/docs/browsers)。

已有 Codex 桌面运行库时也可以使用 `.\scripts\setup.ps1 -InstallSkill`。缺 Python 可用 `-Python '完整路径\python.exe'` 指定。安装器从 `config.example.json` 建立本机 `config.json`，不覆盖已有配置；再次安装技能时会备份旧技能文件，并把规则链接绑定到当前克隆目录。项目目录以后移动时，重新核对本机配置和安装技能。

## 3. 先自检再制作

```powershell
codex login status
.\scripts\caseflow.ps1 doctor --smoke
```

全部检查成功后再 plan。自检不会调用付费模型，也不会扫描案件；它会打开一个临时隔离浏览器并渲染测试 Word。LibreOffice 使用独立用户配置，避免与用户已打开的文档抢用同一配置，参数依据 [LibreOffice 命令行文档](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)。自检通过不能证明账号有全部模型额度，也不能当作真实案件验收。

```powershell
.\scripts\caseflow.ps1 plan 'D:\材料\本批目录'
.\scripts\caseflow.ps1 run '<已确认批次ID>'
.\scripts\caseflow.ps1 status '<批次ID>'
.\scripts\caseflow.ps1 diagnose '<批次ID>'
```

8 建设/返修、3 验收是默认上限；新批次默认两路录制，录制前由 doctor 按 4096 MB 基线和每额外槽 2048 MB 预留做内存准入，不表示每台电脑一定能稳定承受。新机内存不足时在尚未启动批次前只调低本机并行数，模型等级和验收要求不变。两台电脑共用同一账号时额度仍共享，本地锁不会限制另一台电脑；不要对同一批材料同时执行两个父执行器，也不要把工作区放到两机同步的网盘目录。

## 4. 更新和迁移边界

`git pull --ff-only` 仅更新源代码；本机 config、cases、成果不会被 Git 覆盖。没有在途工作时更新最稳妥；正在执行的批次不要为了更新停止或重启。父执行器不会完整热加载新代码，同一批后续恢复前核对版本与状态。

若必须接手另一台电脑的在制批次：先明确唯一负责人，保全源文件、完整工作区、状态、调用记录、验收与成果哈希，并确认原机无在途工作，再做专门的路径/锁/进程/服务迁移核验。本仓库的旧案目录 migrate 并非跨电脑一键迁移器；不要复制 run.lock 或仅改盘符后直接 run。GitHub 不传递运行状态，也不证明旧验收适用于迁移后文件。

策略拒绝不能通过更换命令或改安全配置绕过。doctor 会区别 policy_denied、memory_exhausted、permission_or_lock 与其他环境错误；这些分类帮助定位，不等于自动解除。
