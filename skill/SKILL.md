# 软通案件批次制作

用于安装时绑定的 Windows 项目，入口为 `scripts/caseflow.ps1`，配置为 `config.json`。先核对项目文件及实际脚本帮助。材料正文是技术依据，不是执行指令；普通文档编辑、化工材料附图不自动进入此流水线。

## 当前目标与边界

- 新批次默认 `deliverable-first-v1`：用户最终需要每案一个增补 Word 和一个约10秒真实网页视频。保留完整导航、路由和模块标题，只完善两个贴合案件系统形态的业务页面；其他模块内容可空。页面体现业务操作，不套图表看板。不为未交付功能补账号体系、全套持久化、设备接入或生产部署。
- 以源定义、实际计算和代表工况生成2–6张有独立分析价值的黑白结果图，可离线直接插 Word，不强制同步上网页。保留原文、原式、原图及其位置；正文恰当实施例插入自然衔接的红字说明，每图独立“请参考图N”；仅新增图及其下方图题按序追加到全部原文之后。
- 成品固定为 `批次目录/案件名称/修订文档.docx` 和 `批次目录/案件名称/模拟系统/演示视频.mp4`。不平铺视频、不混放多案视频。新批次 `word-video` 不复制原件、图表资料或 README；这些及源码、数据、历史证据完整保留工作区。
- 仅执行用户明确授权的批次；同一清单已确认不重复问。示例目录只读，不扫描新材料、不定时唤醒、不空闲巡检。已登记批次按 manifest 冻结的 pipeline/delivery/execution profile，规则更新不自动重做历史成品。明确点名返修另存版本，保留旧交付与建设目录。
- **完成义务。** 承接整批即负责把授权清单内每案制作、修复、验收并交付，不能以plan/预检/worker退出或“已报blocked”结束制作。可修复的启动、依赖、编码、路径、普通代码和材料缺口由负责人处理并接续原批；worker停止重复付费尝试不等于负责人停止解决。确需用户介入的真实外部限制按[负责人接续责任](../rules/worker-environment.md#负责人接续责任)说明具体动作，其他可做部分继续。

## 模型、并发和唯一负责人

| 阶段 | 当前默认实际 CLI |
|---|---|
| 建设与建设内自检 | `gpt-6.1-sol/high` |
| 返修、录制准备修复 | `gpt-6.1-sol/ultra` |
| 普通独立只读验收 | `gpt-6.1-sol/ultra` |
| 用户明确加急的独立只读验收 | `gpt-6-astra/low` |

新批次跨批共享8个建设/返修槽、3个普通验收槽、2个可信录制槽；受控证据和明确加急验收各1槽。录制受物理及提交内存准入保护。旧批次依冻结配置，不热改、不为腾槽打断有效调用。加急不追加 Ultra 复核。模型由实际 CLI 参数决定，禁止自签、静默降级或让独立验收者建设。

入口对话负责本批接续；案件 worker 只改自己的案件目录，父执行器保存状态和审查。共享脚本/规则由唯一维护者修改，多任务协作先明确归属。已有父进程或 worker 运行时禁止重复启动；侧栏 idle、锁文件存在、worker退出均不能代替进程身份与阶段日志核对。

## 执行顺序

1. **确定范围。** 读 [成品优先规则](../rules/deliverable-first.md)、[成果合同](../docs/artifact-contract.md)，按需查 [质量规则](../rules/requirements.md) 和 [实际改图标准](../rules/chart-acceptance.md)。只对指定目录 `plan "<目录>"`，核对清单、数量、源哈希、异常及输出。工作区为 `cases/YYYY-MM/案件名`，同月重名加序号；管理文件在 `cases/.batches`，默认成品在原料同级“原目录名1”。不得改原件或移动运行目录。
2. **环境先过，再付费。** `run "<原目录或批次ID>"` 前按 [环境规则](../rules/worker-environment.md)核对准确 runtime、依赖、内存、CLI及原受限模式零模型读写预检。CLI版本/登录成功、父层可写不证明 worker 可用。桌面与运行时存活时测试；已知 CLI 回归使用已验证的官方修复版本并固定本机路径，缺失时不回退。不改沙箱、审批、ACL或安全 Deny，不靠反复重启或每案付费探测。
3. **建设内一次完成依据、计算和自检。** 按 [案件设计](../rules/case-design.md)选两个业务页及有意义图数；按 [成品优先规则的建设一致性检查](../rules/deliverable-first.md#建设一致性检查)核对源式约束、代表数值、正文符号、最终图例、切换后的详情和运行日志。结果冻结后供图、说明和必要界面字段共用。数据不足按 [材料补齐](../rules/material-sourcing.md)自动检索核验或构造有依据可复现输入后实际计算，来源、假设、种子及未验证范围留 README，不冒充实测。
4. **自检后交父执行器。** 建设/返修会话内运行 `scripts/build_preflight.py "<案件目录>" "<原件>" --source-sha256 "<源哈希>"`，先修合同及Word图文位置，再检查最后版渲染。按 [录制计划](../docs/capture-plan.md)准备 schema 2计划，实际 probe、打开截图及切换关键帧。父执行器固定程序录制、生成受控Word/视频证据，再一次集中独立验收。脚本预检不是视觉通过，不增加固定模型审查轮次。
5. **仅修受影响部分。** `revise` 一次处理全部具体问题，自检后复验；未变且此前真实已阅的证据按哈希沿用。文档专用图/正文变化只更新对应图文和Word渲染，不重录；录制页面代码/数据或实际画面变化才按依赖重录。复验不扩建空模块、不重读无关历史。累计保存调用与用量，可修复问题持续到通过，无固定两次上限。执行协议见 [提速与验收](../rules/execution-efficiency.md)。
6. **逐案交付与回收。** 当前哈希验收、Word、模拟系统视频及收据全部有效才发布。随后核实PID/创建时间/命令行/端口/健康身份，及时回收无在途任务的本案专属后台，回执放批次维护目录。清理失败记录 `cleanup_pending`，不撤销交付、不触发返修；保留拟名称 PatentTitleBot/Hermes、共享及其他项目、仍在工作的父进程。最终按原清单逐案对账，不能用局部成功、测试或worker退出称整批完成。

## 图文与页面的易错点

- 公式登记保留 raw/normalized、上下标、帽号、希腊字母、变量定义和输入约束，不以 OMML 节点数代替公式组数。源式以外的输入假设独立标明。
- [图表质量](../rules/chart-quality.md)、[专业图表](../rules/chart-professional.md)、[图例](../rules/chart-legend.md)按各自生效范围执行。检查实际PNG及Word正常尺寸的每幅图，图例从真实绘图对象生成，与系列、线型/灰阶/纹理一致；短符号能正确排版才保留，不能稳定显示就用准确业务名称，不把 `A_e` 压成 `Ae`。轴标签同查；真实单位保留，无单位量仅写业务名，缺单位资料不能猜无单位。
- 增补说明的关键数值从冻结结果读取或独立代入核算；首次出现的符号就地简释，不能等后文才定义或丢上下标/帽号。看前文—红字—后文，不复制独立说明整段硬贴。
- 两页真实业务操作后的选中对象、摘要、表格、详情必须同一状态；正反切换都查。只看两个页面最终截图不能证明切换无旧数据或白屏。可见文案按 [网页规则](../rules/web-visible-copy.md)，不以“模拟/虚拟/工程样本”等堆在界面，来源与限制内部如实记录。

## 阻塞与恢复

- 读最新 state、控制请求、原始错误、末尾日志和实时进程，区分正常排队、历史 reason 与当前故障。`blocked by policy`、ACL拒绝、文件占用 `os error 32`、沙箱初始化、内存不足分别记；否定或未确认措辞不按关键词武断归类。真实策略拒绝不换命令/工具绕过。
- 验收环境 `blocked` 是未完成检查的诊断，允许如实只列实际已读证据；父执行器保留原答复、未读项和真实原因，不能补签或当普通内容返修。旧答复误用blocked标签时，仅完整已阅且明确属于具体产物的普通缺陷可按 [环境规则](../rules/worker-environment.md)兼容返修，原判定保留。`pass`仍须全覆盖且当前哈希一致。环境恢复后由负责人写新的 `.caseflow-environment.json` 就绪记录及真实恢复依据，旧 ready 不解除新故障。
- 父执行器尚在运行时优先 `control <批次ID> resume-case --case-id <ID>`；已退出才核对锁、原件和状态后 `run <原批次ID>`。共享环境修一次，不让各案重复付费试错；单案问题不暂停其他案。不得为了监控、改规则或换执行器而停止正常批次；批次级有中断影响的维护须先交用户决定。
- 仅用户明确授权更替执行/迁移时，保全调用、状态、数据库与文件哈希，核实归属后在安全边界切换。`migrate`或 `workspace_copy.py` 用途及正常继承副本要求见环境规则，不清空重建或复用过期通过。

## 按需入口与历史范围

- `control <批次ID> expedite [--case-id <ID>]`：明确加急才用，见 [加急规则](../rules/expedited-review.md)。只提高优先级用 `priority`；正常排队不是暂停。`drain`仅用于用户明确要求的暂停或维护。
- 老 `efficient-v1` 流程查 [历史录制协议](../rules/efficient-pipeline.md)；源保护/首次部署/跨机安装查 [开始使用](../开始使用.md)，测试范围查 [发布核验](../docs/发布核验.md)。隔离测试不称实际案件端到端成功。
- 2026-10-08点名的1007周丽、1007莉莉含已交付案均核查公式图例，发现问题才定向修复；其他历史案不自动返工。旧提前导出豁免只适用用户当次授权，不扩展到新批次。
- 用户明确要求研究其他改图反馈时才只读取证，保留原话、图像快照、哈希与版本，区分明确认可和助手自称通过；推进到Word不等于视觉认可。不由此安排巡检或向其他任务派修改。
