# 执行结构

`scripts/caseflow.ps1` 从同一项目的本机 `config.json` 选择 Python，调用 `caseflow.py`。相对路径按配置文件目录解析，不依赖当前终端位置。

`plan` 只登记用户指定目录和原件哈希。清单确认后 `run` 获取批次锁，在本机工作区共享建设/验收/录制槽间调度；冻结批次的流程和交付协议，后续默认配置不自动迁移旧批。每案保留自己的端口建议、浏览器、临时目录、状态、实际模型参数、累计调用及材料哈希。

新批次 `deliverable-first-v1`：建设与自检 → 固定程序录制 → 父执行器生成受控 Word/视频证据 → 一次集中独立验收 → 按具体问题定向返修及受影响证据更新 → 原子交付。Word 专用图变化不使未改变的录制页面失效，其他网页模块可保留空框架。视频只由当前页面、录制计划和输入哈希证明其版本，不能用旧通过覆盖新文件。

`controlled_evidence.py` 生成全页渲染、原文/源式/原图保留检查及视频时间线，验收模型只读这些真实证据。`render_word.py` 是独立可部署的 LibreOffice/Poppler 包装器，使用本次专用 Office 配置，不依赖原电脑的插件路径。

交付先写本批 staging，逐文件校验后保留发布意图，再原子改名；恢复时比对原件、审查和成品哈希，不覆盖其他交付目录。成品固定为每案根目录的 Word 和该案 `模拟系统` 中的视频。

`runtime_doctor.py` 负责运行库、工具和 CLI 登录预检，无付费模型调用。安装器不覆盖已有本机配置、不迁移运行中案件、不复制账号数据，也不调整安全规则。批次锁与共享槽只在同一本机工作区内有效，跨电脑不是分布式调度。

案件 worker 仅修改本案；全局执行器由维护任务唯一修改。正常运行不因巡检、汇报或升级被暂停。交付后由负责人核实并回收本案不再使用的后台；这个责任不能靠全局批量杀进程实现，当前未添加无身份依据的自动杀进程功能。
