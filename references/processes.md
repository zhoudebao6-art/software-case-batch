# 本案后台收尾

所有服务启动前记录归属，服务命令使用案件文件的绝对路径；Windows `Start-Process` 使用 `-WindowStyle Hidden`。启动后用 `process_guard.py register --workspace ... --pid ...` 登记每个专属进程，包括独立前后端、任务工作进程和专属启动器。登记会校验命令行含本案完整有界路径，保留父PID、创建时间、命令行摘要和监听端口。

命令行没有本案绝对路径的子进程须先核对父子链和独占用途，调整今后的启动方式；工具不会仅凭 `node.exe`/`python.exe` 名称杀进程。浏览器由录制器持有并在 finally 关闭，不处理用户已有浏览器。Codex/MCP、PatentTitleBot/Hermes、其他项目和共享服务保留。

录屏、在线测试和所需截图完成后运行 `stop`。工具使用登记时创建时间和命令行与当前 OS 信息核对，并持有 Windows 进程句柄后再核验、结束同一进程，避免 PID 复用。逐项重新读取退出与端口情况，扫描本案仍存活的命令行，未登记但属于本案的后台记 pending；核实后登记并再次收尾。发现拒绝或权限不足不绕过、不声称成功。

顺序通常是专属工作进程→前端→后端→专属启动器；不要先杀启动器使关联证据丢失。有正在执行的有效项目任务时不强停；当前工作完成后关闭。运行中的数据库文件、软件和证据全部保留。`cleanup.json` 不是自签声明，必须由工具读取实际 OS 状态生成；最后状态不是 `stopped` 时不得通过新版全部完成门禁。
