# 系统深化与数据

本文件全部要求用于以后每个授权案件，测试案修改没有单案豁免。字段、算法及业务动作按本案定义适配，不照搬上一案名称。

## 系统需要做厚的部分

先盘点已有实现与原定义，列出每个核心业务动作、算法入口、输入边界、落库表、页面、导出和验证命令。复用有效计算与图文；发现当前图文与算法不一致，定位修复并重验受影响部分。

建设内按原文允许的业务状态核验重复、迟到、冲突、跨版本及撤销后回执，确认身份/占用/版本和终结条件先于状态修改检查。已确认终结与仍在途未确认不能混用分支；出现矛盾时按原文保存异常并停止自动转换。测试覆盖正常允许路径和本案真实禁止路径，不把某案的终结规则硬套到所有案件。

算法增强应解决本项目的问题：数据校验、量纲及边界、缺测/异常处理、关键约束、参数配置、状态转换、批量计算、历史追溯、性能和稳定性。需要优化/预测时实现实际求解或推断与可核对的基线，不用硬编码结论或没有调用者的“算法大全”凑代码。物理量按领域机理计算，业务类项目按可解释事件、约束和流程计算，不强套无关物理模型。

Web 以案件用户的工作过程组织，所有导航和按钮均有实际业务内容或清楚的合法不可用状态；不能用空页面、装饰按钮或弹出“成功”代替执行。常见模块可包含对象档案、任务/计划、运行监控、事件处置、结果详情、历史记录、统计和参数管理，按项目取舍，不机械凑页数。工业类使用对应工业控制界面，调度、医疗、监测等按各自对象设计。

中文标签与完整中文错误提示；仅保留单位、型号、通行缩写等必要英文，不展示技术术语堆砌、推导或内部流程。数据密度与层次并重：可筛选表格、排序分页、对象联动、详情抽屉、表单校验、提交反馈、状态流转、历史追踪、图例/时段交互和可下载导出。刷新与服务重启后保存结果仍存在。并发点击、空结果、网络失败、权限不足有真实处理，不吞错。

通用业务状态验收：任何创建、提交、调整或状态动作成功后，按本案实际可见项检查列表、详情、统计、摘要和日志引用同一对象和计算/业务版本；不能仅更新抽屉而背景保留旧状态。重取数据保留用户当前筛选、排序及仍合法的分页，越界页合理回退；关闭抽屉后用请求序号/取消等机制阻止迟到响应重新打开，连续点击及正反切换也实际测试。无对应界面项的项目如实记录不适用，不为凑该检查扩建无关业务模块。

交付源码包含配置范例、锁文件、数据库初始化/迁移、启动与停止入口、生产构建、健康检查和实际可用备份恢复脚本；使用/运行/安装/部署说明及日志留内部工作区，不放ZIP。按用途实施认证授权、密码安全存储、服务端校验、参数化数据库操作和密钥外置。不要预置可公开使用的固定管理员口令。实际验证本机部署条件；没有目标主机、域名等时记录待部署，不擅自上线。

## 开源检索与足量数据

先检索同领域开源仓库及仓库指向的正式数据集，至少核对一个实际适用且可取得的数据入口；尽量比较两种来源的适用性。保存 URL、仓库版本、访问时间、许可、下载文件哈希、字段/单位、筛选范围与适配决定。只有搜到介绍页不算取得原始数据。无法取得时如实记录具体检索与限制，使用本项目定义完成可复现计算，不捏造引用或下载成功。

在内部 `data-plan.json` 明确实体数、时间范围、采样间隔、关键事件与边界工况、预计行数、表间关系和验收指标。高频时序项目可从 30–90 天、多对象、十万行级计划；业务记录项目可从万行级主/明细与关联事件计划。它们是体量起点，最终规模由领域粒度、运行时长与硬件确定；合理较小规模要解释，禁止复制行、独立随机列、无物理关系或不可能频率凑量。

建设开始先统计清洗后实际交付的重要CSV有效行数、独立对象数、时间跨度及事件覆盖，作为本案扩量基线；不把计划行数、重复分片或中间表合计当有效交付量。主要业务明细先以现有效规模约2倍为规划起点，再按业务粒度、约束及运行性能调整；维表、汇总表无需逐表翻倍。新案没有实测旧规模时基线留空，以本案领域及可部署性能明确足量目标，不编历史基线、不退回少量样例。偏离2倍规划起点须在现data-plan说明实际业务或性能原因，不能用理由掩盖重复数据。

优先扩大合理时间范围、独立对象和正常/边界/异常/恢复场景，保持对象关系、采样频率及可复核计算。扩量由可复现领域批量脚本完成，不让模型逐行编造，不复制行或仅换行编号，不重复导出同表，不独立随机填列；扩展记录不能改称现场采集。建设自检比较实际扩容前后规模、场景及跨表关系，验证扩量后的Web列表分页、筛选、下载与源码从这些CSV初始化，不能只有CSV增加而系统继续使用旧数据。

计算保留种子或确定性配置、参数、机理约束、扰动与运行日志；检验范围、分布、相关性、时序连续性、守恒/约束、主外键、重复、缺失和异常占比。训练类任务按时间或实体隔离划分，防止泄漏。所有字段具备类型、单位和业务含义。公共数据用于校准范围与分布，不改变其出处，更不能把扩充结果称现场实测。

## 重要 CSV 选择和清洗

重要性按用途选：业务实体、主时序/记录、事件、关键算法结果和必要汇总。排除调试转储、重复备份、可重建的中间宽表、分片重复和空 CSV。选择写入明确白名单，每项给出用途、主键、最少行数和重要性理由；不递归复制所有 CSV。

数据目录仅交付 CSV，UTF-8 BOM，保留字段顺序、数值精度、时间戳、标识、空值与原行序。整列剔除“生成数据”“数据来源”以及工具明列的同义元数据；其他列不得猜测删除。“生成时间”等业务列不自动去掉。剔除指定列后若值或文件名仍有禁词，报告行列定位，先按语义修复再导出，不把业务值自动删改。输入文件不修改，清洗记录和出处保存工作区。

交付CSV文件名、列名和单元格（含备注、描述、嵌套文本）不得含真实或编造的地名、公司名、人名；公开输入在适配时就改为中性稳定的对象/主体/操作员/区域编号。专名列按业务需要改成对应编号字段或移出白名单，不以“某市”“某某公司”“张某”等代替。普通业务术语、角色及单位保留，不能粗暴关键词删除。内部原始材料、映射、来源及生成性质完整保留，不改原Word或第三方必要署名。同一对象跨表、时间、主外键及Web下载使用同一映射；`data_preflight.stable_entity_id(namespace, source_key)`可给中性namespace和稳定源键生成确定性编号，内部映射不交付，不声称哈希编号实现不可逆匿名。

## 建设阶段实际CSV检查

新`data_policy_version=neutral-expanded-v1`在既有`.product-v2/data-plan.json`保存以下字段，沿用导出白名单及自检/清洗记录，不新增台账：

- `export_schema`：以实际交付CSV basename为键，逐列按实际顺序声明`columns`及`kind`（id/number/timestamp/enum/text）。id给中性`pattern`，enum给业务`values`；person_name/company_name/geographic_name类型和专名字段不得交付。每表声明`primary_key`、`effective_key`，按需要声明`object_columns`、`time_column`、`event_column`及`foreign_keys`；主明细有效键含实体、时间/事件/结果等真实业务内容，不只用替换后的行编号。`primary_key_kind`默认`surrogate`，有效键不能只使用这种行主键；自然业务复合键显式写`primary_key_kind=natural`，允许主键和有效键相同，但两者均须含声明实体ID与真实时间/事件语义，或至少两个经类型校验的number/timestamp/enum业务字段。纯ID主明细及用自由文本冒充业务语义仍拒绝，实际重复仍会失败。合法维表可标`table_role=dimension`并使用其业务主键，不要求维表翻倍。
- `known_names`：原始输入和适用公开来源中已知专名，仅在内部记录，实际检查文件名、列名和所有单元格，包括常见转义后的嵌套文本。`allowed_terms`是明确正常业务词的精确白名单，不豁免已知专名命中。
- `name_review`：逐CSV当前`sha256`、`filename_checked=true`、`columns_checked=true`、`text_checked=true`及具体非空`evidence`，只由high实际看过当前CSV后记录。枚举/编号schema和已知名单不能认识全部未知或编造专名；自由文本、文件名和列名继续实际检查。不把删掉几个姓名列或脚本无命中当完整去名。通用审查声明不能覆盖已知专名、非法schema、重复或主外键错误；内容变化后旧hash检查失效。
- `baseline_metrics`：原清洗后真实统计的`files`映射；每个主要表至少有实际`effective_rows`并保留对象/时间/事件统计。新案用`{}`，不能写虚构的旧统计。
- `expansion_plan`：`generation_method`写可复现领域批量脚本及参数/种子位置，`main_tables`仅选择主要明细表；每项给`target_effective_rows`、适用的`required_events`，低于实际旧基线2倍时写`adjustment_reason`。新案必须显式给领域合理目标，未指定的维/汇总表不强制扩量。

例如以下结构用于说明字段，表名、主键、状态、目标及review哈希必须换为本案实际值；不能原样当验收证据：

```json
{
  "export_schema": {
    "对象.csv": {
      "table_role": "dimension",
      "columns": {"对象编号": {"kind": "id", "pattern": "OBJ_[0-9a-f]{64}"}},
      "primary_key": ["对象编号"], "effective_key": ["对象编号"]
    },
    "记录.csv": {
      "columns": {
        "记录编号": {"kind": "id", "pattern": "REC_[0-9a-f]{64}"},
        "对象编号": {"kind": "id", "pattern": "OBJ_[0-9a-f]{64}"},
        "时间": {"kind": "timestamp"},
        "状态": {"kind": "enum", "values": ["正常", "边界", "异常", "恢复"]},
        "值": {"kind": "number"}, "备注": {"kind": "text"}
      },
      "primary_key_kind": "surrogate", "primary_key": ["记录编号"],
      "effective_key": ["对象编号", "时间", "状态", "值"],
      "object_columns": ["对象编号"], "time_column": "时间", "event_column": "状态",
      "foreign_keys": [{"columns": ["对象编号"], "target_file": "对象.csv", "target_columns": ["对象编号"]}]
    }
  },
  "known_names": [], "allowed_terms": ["已处理", "待核对"],
  "name_review": {
    "对象.csv": {"sha256": "当前对象CSV实际SHA256", "filename_checked": true, "columns_checked": true, "text_checked": true, "evidence": "实际检查中性编号及文件名列名"},
    "记录.csv": {"sha256": "当前记录CSV实际SHA256", "filename_checked": true, "columns_checked": true, "text_checked": true, "evidence": "实际检查全部备注及文件名列名"}
  },
  "baseline_metrics": {"files": {"记录.csv": {"effective_rows": 1000}}},
  "expansion_plan": {
    "generation_method": "本案确定性领域批量脚本，参数和种子保存在内部既有计划中",
    "main_tables": {"记录.csv": {"target_effective_rows": 2000, "required_events": ["正常", "边界", "异常", "恢复"]}}
  }
}
```

若本案记录天然由对象、时间和状态唯一确定，可将例中的主明细改为`"primary_key_kind":"natural", "primary_key":["对象编号","时间","状态"], "effective_key":["对象编号","时间","状态"]`，保留对应object_columns/time_column/event_column及真实类型；声明time_column必须为timestamp类型。只有实体加一个业务字段时须有匹配的time/event语义声明；两个以上经类型校验的非ID业务字段可使用前述另一合法分支。无需为了通过检查额外制造行主键，也不将纯编号键标成natural绕过扩量校验。

high在数据适配/导出环节先用`data_preflight.audit_csv_exports`检查准备交付的实际CSV；它只读且逐行检查，不修改源材料或静默删除单元格。完成`clean-data`后，运行`proflow.py check-data --workspace '本案绝对工作区'`重读实际候选CSV并调用`check_expansion`，结果存入现`data-cleaning.json`的quality。`data_status=fail`必须修复；`review_required`说明当前hash的真实专名检查未齐，不是通过。确定性检查只涵盖声明schema、有效键、已知专名、哈希绑定审查和可定位的引用，不能自动证明完整语言专名识别、领域机理正确或现场实测。建设者仍验证计算、关联、汇总及页面/初始化一致性。finalize按实际当前文件再次计算并要求与已有quality匹配；旧run数据合同冻结，不追改历史收据。

代码和 Web 同样禁止用户列出的中文词；程序结构、数字运算、必要英文标识不受中文文案检查误伤。新编写的代码注释和字符串也要检查，不通过 Unicode 转义或拼接藏词。第三方必须保留的许可证文本集中放源码包的 `LICENSES`，单独核对法律保留，不删署名。原 Word 不做禁词替换；固定成品容器目录 `模拟系统` 仅名称豁免。

源码通过显式白名单压成成品 `模拟系统/项目源码.zip`，不直接复制整座工作区。排除所有层级、任何大小写的 README 与变体，以及针对原技术文档的解析、抽取、公式登记、原文映射、分析报告、解压媒体目录。业务系统自身需要的文件导入/解析模块应保留，不把所有名叫 parser 的业务代码一概删除；遇不明确文件，核对用途后加入排除表。源码包必须能从清洗后的外部 CSV 初始化数据，不能暗中依赖被排除的技术材料或旧工作区绝对路径。原工作区被排除文件完整保留。

源码ZIP内不放使用/运行说明、制作过程、原件解析和数据构造/来源说明，也不放揭示模拟性质的文案。内部README与数据出处如实保留数据性质、计算扩展过程、假设和未验证范围，不因排除交付说明删除证据或改称实测。必要第三方署名/入口/DOI/许可URL及变更指示集中许可证，法律必要内容保留；非必要制作用语也走语义审查，LICENSES不能作全文件藏说明豁免。不在每行CSV重复性质列，不在界面堆标签。
