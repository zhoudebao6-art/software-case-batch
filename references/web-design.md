# 按案件业务制作 Web

适用于本技能的系统建设及用户明确要求的界面调整。与 `system-data.md`、本案原技术材料一起使用。目标是不同业务有各自合理的工作界面，并且界面操作真实调用本案算法与持久化。

## 从案件业务确定完整页面

从本案全文、实施例、对象和用户任务确定使用者、输入、技术处理、处理结果、后续处置、历史与导出。沿已有 source_trace / coverage_matrix 或建设计划，把每项本案适用能力对应到页面、实际函数/API、状态/存储和结果去向；同一资料复用，不另建审批或独立设计阶段。先读完整材料再定功能范围，不能只挑两个方便录制的交互。

默认规划8—12个有独立业务目的的模块，可为可导航页或明确功能分区；按源技术和生命周期选择对象、批次、采集输入、配置、处理、诊断分析、处置复核、历史比较、报表导出等适用功能。不得用同表换名、关于页、空页面、统计卡或重复面板凑数。小案及特殊领域可合理调整，在现source_trace、coverage_matrix或建设计划一句说明，不另建台账或审批，不强加无关功能。独立页面提供清楚导航与返回，同一任务的联动区域可共处一个工作台。每个承诺的页面都要有本案有效内容和实际操作，不允许把未实现核心模块标成“暂无数据”或以空菜单充数。正常无结果、无权限或不满足前置条件应有真实原因、下一步及恢复操作。

工作台优先围绕“选对象/任务—输入或配置—执行—查看与处置结果—保存/历史—导出—继续下一项”组织，可按案件省略确实不适用的环节并解释依据。不是每案都加账号、财务或后台管理；也不是三张统计图加表格就构成完整系统。所有领域仍以原技术定义为准。

主工作区先承载本案最有辨识度的对象；对象、信息组织和操作顺序决定布局。以下是可选择的方向，不是固定套版：

| 业务特征 | 主工作区方向 | 有意义的交互 |
| --- | --- | --- |
| 图像/视频、几何检测 | 原始影像/空间视图和处理结果联动的检视台 | 输入/选样、实际处理、结果对照、按算法支持的定位与复核 |
| 事件关联、故障调查 | 时间轴与事件关联视图 | 时间窗筛选、关联定位、处置前后对照 |
| 反应、训练或批次预测 | 批次工作台与参数结果对照 | 参数约束、版本比较、预测核准 |
| 农业、分区控制或流量调节 | 分区作业视图与控制曲线 | 分区选择、处方调整、反馈对照 |
| 排程、资源或能量调度 | 任务时段与资源占用视图 | 冲突定位、排程调整、执行进度 |
| 对象登记、审核或信息处理 | 工作队列与详情联动 | 条件组合、逐项处置、状态追踪 |

同批读取已有案件的简短设计画像，不重新打开全部成品。不同业务若仍是同一导航、同一指标卡排列、同一表格抽屉结构，先调整主工作区、信息层次或关键交互；仅换标题、颜色、图标不算差异。相同领域可以保留有用的操作习惯，不能为追求不同而破坏可用性。

新建界面或用户明确要求改版时，读取[页面质感与文案取舍](web-presentation.md)，在已有简短设计画像中确定主对象、阅读密度、视觉方向和角色样式；不另交设计报告。优先做实模块与数据，纯风格微调只作建议，不列返修或阻塞。通用表格、表单、认证和图表基础组件可以复用，页面结构与领域数据绑定按本案制作。

## 按系统类型做真实业务界面

以下为取舍依据，按原材料组合，不是每案必须照抄的导航清单：

- 工作台/业务处理：有可定位的对象或任务队列、任务状态与约束、主体操作区、必要参数和详情、明确处理反馈及后续去向。连续处理第二件、回看第一件、刷新和返回后不能串对象或丢结果；队列、详情、统计、历史同步。
- 视觉识别：用户可上传或选择与案中对象匹配、合法可用的真实图片/帧；后端实际解码和按案中方法处理。原图与识别结果、对象/缺陷或适用量测对应展示，可缩放、局部检视、切换输入、复核和导出。分类展示实际类别依据；检测/分割仅在算法真正输出时展示框、掩膜或位置；不强塞无依据的置信度。用至少两份内容不同的代表性真实输入核对输入哈希、处理入口和实际输出，再核适用的无目标/不支持/损坏输入分支。不能只根据文件名查固定结果、读预置标签当预测、上传后仍展示同一结果，或用生成图、装饰图、人工预画框冒充真实图像识别。真值标注与推理输入隔离；不存在可用训练权重/条件时如实处理，不把占位分类器称已实现源方法。
- 监测/故障分析：设备/区域、时间范围、原始观测、趋势/事件关联、异常定位、处置与历史按源机制联动，不能只有汇总卡片。涉及图像、波形或空间数据的真实输入保留其适合的主视图，不全部压成数字表。
- 控制/调节：围绕对象、目标值/约束、当前状态、控制决策、执行/反馈与异常来设计；展示原方法的时序和适用边界。无真实硬件连接不能宣称已经现场执行，不为页面动效伪造设备回执。
- 调度/资源配置：任务和资源、时段/空间占用、约束、实际计算后的方案、冲突/不可行原因、调整和执行记录可操作、可比较，改变输入应影响实际求解，不以固定甘特图替代。
- 材料/工艺/实验分析：围绕样件、批次、工艺条件、检测量、适用曲线、处理结果和比较记录，结果与本案实际输入及技术计算绑定；不要套成与案无关的设备监控或故障看板。
- 信息审核/评估：对象资料、输入完整性、任务队列、实际判定过程、可解释结果和后续处置/记录是主体。医疗筛查等不得把工程核验写成临床有效或扩展未支持诊断。

必要真实图像、视频片段/几何文件、模型权重和许可是系统的运行资产，通过源码白名单随可启动ZIP交付；数据目录仍按既有CSV格式。不能把运行图片当成制作附图而清走，也不能让ZIP依赖旧工作区绝对路径、临时下载地址或未交付权重。原始出处/许可、真值及验证记录留内部，必须随资产分发的许可证保留。图片来源真实和领域适配须由建设者与首次审核者实看，脚本只能核文件/解码/哈希及证据绑定。

## 用户能理解的文案

页面、提示、错误、导出预览和初始化空状态使用业务语言。按[文案取舍](web-presentation.md#文案去除按需展开必须保留)去除制作过程、自夸和实现证明、重复标题引导及无助操作的原理长文；仅与当前决策相关的补充帮助按需展开，内部说明直接移出界面，不藏入折叠框。单位、阈值、约束、重要风险和不确定性、错误恢复必须保留。明确禁词复用 `ui-policy.json`；“生成报告”“计算结果”等正常业务词不一概禁用，也不改成未经证实的“实测”“现场采集”“生产运行”。

原材料、计算假设、数据性质和出处继续如实保存在内部证据中；修改界面文案不删除证据、不修改原 Word，也不改变算法含义。

## 建设时一次做对

沿已有浏览器自检实际访问每个业务页面，核入口/返回、对象/参数传递、主操作、详情/列表/统计同版本、错误反馈、空结果、保存重启和真实导出。把各任务的输入、动作、预期与实际结果绑定原browser日志和当前截图；截图和“操作成功”字样不能单独证明后端完成。表单有明确标签，键盘焦点可见，提交期间有反馈；长表按业务分页或按需加载，图表选中对象与其他视图同步。截图用于判断布局与内容是否专业，不能用截图替代真实点击和业务断言。

异步结果在写入任何可见状态前核对请求发起时的对象ID、版本与当前请求序号；操作、计算、图表、提示和详情各自的回调都适用，不能只保护refresh。中途切换对象、改变筛选或关闭详情后，迟到结果不覆盖当前页面，也不重开抽屉；后台已完成的真实操作仍保留。建设内用一次延迟响应加切换/关闭动作验证本案实际消费路径，沿已有浏览器日志记录，不新增审核阶段。录制计划的搜索清空也实际执行一次，不能只检查非空输入。

可直接将技能的 `assets/web/request_scope.mjs` 复制到本案运行源码并按框架接入；已有等效可靠机制则沿用，不为升级重写成品。组件仅管理请求归属，不提供通用业务算法，也不替代本案浏览器自检。对象/输入版本变化时 `scope.enter(对象ID与版本组成的键)` 并清除旧详情、旧错误和加载状态；空结果或关闭时 `scope.close()` 并清空选中对象。每个独立显示区域使用不同lane，同lane只接受最新请求：

```javascript
const ticket = scope.begin('detail');
setBusy(true);
try {
  const response = await fetch(url, {signal: ticket.signal});
  if (!response.ok) throw new Error('加载失败');
  const value = await response.json();
  if (scope.isCurrent(ticket)) setDetail(value);
} catch (error) {
  if (scope.isCurrent(ticket)) setError(error.message);
} finally {
  if (scope.finish(ticket)) setBusy(false);
}
```

所有成功、错误和finally可见写入均受归属保护，切换对象即使旧请求忽略取消也不会覆盖新页。取消前端请求不代表撤销后台写操作：真实写入仍按服务端事实保留，重新加载当前对象确认结果，不盲重发。输入修订必须传新版本键；搜索清空时实际清空选择和依赖视图，不能只引入组件却不接实际路径。复用现有延迟响应/切换/关闭检查即可，不增加审核或录制轮次。

在同一次high浏览器自检里，把这些实际页面状态的可见文字交给现有 `record.cjs` 导出的 `auditUiText` 检查，复用 `ui-policy.json`，问题在录制前修正；录制的既有observe仍检查实际可见文字。词表只识别明确禁词，不能判断所有冗长文字、信息层次或页面质感，这些必须对照当前截图和真实操作检查；不另建文案检查模型。

在原建设自检与首次独立审查里查看全部业务页面及主要交互状态的当前实际截图和操作结果，同时按[页面检查](web-presentation.md#在原检查中实看)核主次、可读性、密度、文案取舍和状态一致性，并按原技术能力检查遗漏；不以截图数量、页面总数或录到了三页代替实际阅读与完整性。主体任务缺失、空壳模块、静态图冒充识别及输入未进入真实处理均属实质缺陷，不按外观小瑕疵放行。问题在原审查一次列齐并定向修复，不增加设计审批或新的整案审核阶段；已冻结历史不因新指南自动重做。无业务用途的装饰与重复流程不增加质量。

## 在原建设检查中记录覆盖

新完整run冻结 `web_experience_policy=case-workflow-v1`，历史run不回填。已有 `.product-v2/build-checks.json` 增加 `web_experience`，复用 `checks.browser.input_files` 的当前文件SHA256与原浏览器运行，不另写第二份通过收据。完整字段见 [Web证据字段示例](web-evidence-example.json)；示例仅说明结构，单页单任务不是交付模板，也不是实际执行证据。

| 字段 | 填入已有的真实事实 |
|---|---|
| `system_types` | 本案类型小写标识，例如 workbench、monitoring、control、scheduling、process、analysis；涉及图像识别必须含 vision，可组合 |
| `source_mapping` | 已有原技术映射文件相对路径，不另抄完整原文 |
| `pages` | 全部业务页 id、route、purpose、workflow_ids、实际截图 screenshot；有区别的业务路由，不拿同页锚点冒充页面 |
| `workflows` | 每项主体任务 id、purpose、implemented、source_refs 中 path/locator、page_ids、actions、expected_result、implementation_paths、assertion_ids |
| `report` | 已有browser实跑输出JSON路径，含当前 run_id/source_docx_sha256；assertions 中记录每个 id/workflow_id/page_ids/action/expected/actual/passed/evidence_paths，具体实际值与状态而非只填“成功” |

引用的映射、截图、源码、报告与结果文件都在工作区内，并由现有browser依赖表绑定非空文件和当前哈希；实现路径还需对应源码manifest及implementation_hashes。source_refs定位原段，页面与任务双向关联，实际断言覆盖声明的动作和页面。脚本检查缺项、未实现/未测、失效引用、文件改变和图像可解码，不会替模型认定功能清单已覆盖整个原案，也不会把一张截图当作真实交互证明。

视觉类的同一report再含 `vision`：workflow_id关联已声明任务，task_type写源定义的真实方法；samples绑定至少两个像素内容不同的真实输入、当前input_sha256、来源与许可内部记录、实际backend.entry_path/entrypoint/request_id、output及实际对照断言；edge_cases记录实际失败或无目标检查。结果证据JSON绑定run/source/input/request身份与result，这是内部运行包装，不要求对外API增加制作字段。合法无目标结果可以是 `status=no_target,result=[]`，不能用无状态的空对象冒充处理。照片真实性、许可和方法正确性仍须实看出处、输入、源码和输出。

`check-build` 及现有capture/finalize路径读取同一记录；首次 `review_packet` 在既有必读索引里纳入所有页面和任务证据，机械生成 `review_scope.web`，无需父另抄一次。审核者在原检查结论中说明本案业务完整性和系统形态是否匹配、视觉输入是否确实驱动算法；哈希和字段完整不等于独立通过。图片/页面改变只更新受影响检查，已冻结交付不自动重做，也不新增一轮收费审核。

## 2026-10-21 新完整案件真实模块下限

rich-delivery-v1至少6个真实模块，数量不设上限，8—12为可调整规划起点但不得低于6。模块可以是独立导航页，也可以是同页有明确入口/定位与业务目的的功能区；空页、关于、统计卡、同表改名或重复动作不能计数。沿原web_experience.modules记录`id/purpose/ui_locator/page_ids/workflow_ids/assertion_ids`，绑定原browser报告真实动作断言；每个模块有独立动作，不重复借用同一断言。门禁只核结构和字节，原自检/首次审查仍对照技术材料实际核主体功能完整。

沿原browser自检保存全部页面证据，从中选一张代表核心业务的原生PNG交付；`delivery_screenshot={path,page_id,native_width,native_height,resized:false}`引用对应pages.screenshot及原browser.input_files。至少1920×1080，可更高，正常字号可读，不放大。用`export-screenshot`逐字节导出，原check-build和首次独立审查核当前绑定；不新增每页交付PNG要求或整案审核循环。
