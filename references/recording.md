# 一分钟真实操作

新版录制器独立于原十秒 `capture_page.cjs`；旧配置和旧批次不受影响。调用工具见 tools.md。

用户本次明确多开要求适用新版新批次：[并发录制](recording-concurrency.md)规定默认auto最高4路、显式2/3/4、模型槽与媒体槽分离、CPU/内存保护和旧批兼容。父启动每案独立进程，capture传齐batch-root/batch-id/case-id/record-token/owner-pid，launch前复查active槽及实际资源。真实操作、画质、完整证据和独立验收要求不变。

用真实浏览器验证整个业务流程；最终录制调用在同一浏览器会话检查就绪并开始连续录制，不再额外启动/关闭预热浏览器。为录制准备 JSON 计划：本机 HTTP 地址、健康接口和启动时冻结版本、就绪选择器、目标 60 秒、输入文件哈希绑定列表和按秒排列的操作。健康接口、当前OS监听身份、登记PID/创建时间/命令行与本案一致才录制，录后复查。至少六次操作、三类操作，时间分散至最后十秒，任意两步之间不超过十五秒，每个改变界面的步骤给出可见断言。根据业务内容安排：概览→筛选/查询→对象详情→参数或任务提交→执行结果/历史→导出和返回。不能为凑录制步骤添加无意义点击。

录制器只支持 `click`、`fill`、`select`、`press`、`download`，每步 `expect` 是等待可见的选择器，可附 `text` 校验。提交后断言业务结果，必要时在独立测试中检查接口、数据库和刷新持久性；可见文字出现不能单独证明落库。下载由浏览器真实事件取得并记录文件哈希。

输入文件列表包括影响页面的实际业务逻辑、前端代码及只读输入，不能只列 index.html；会变化的业务库另作前后快照并验证合法状态变化，不纳入不变文件哈希集合。录制前后核对不变依赖，页面脚本报错、HTTP 失败、禁词、断言失败或版本改变都失败，不把旧视频充当本次结果。

原连续 WebM 和截图保存在 `.product-v2/recordings`。FFmpeg 仅允许裁去导航就绪前的前导段、保留连续操作段并编码，不拼接、变速、循环或補帧延长。FFprobe 检验 55–75 秒、1920×1080；FFmpeg 完整解码。操作事件记录真实开始/完成时间与截图、文字、下载，末尾真实页面保留至目标时间。

自然实操节奏：在真实点击前平滑移动鼠标，输入框逐字键入，关键结果留出阅读停顿；光标标记仅跟随实际指针事件，不得改动业务 DOM 或数据。可用 `storage_state` 指向本案内部真实登录取得的会话文件，禁止带入源码包。录制期间停止本案构建、文档渲染和批量数据计算，避免争抢处理器造成鼠标卡顿；不为此结束其他项目。文本断言等待实际异步结果，不能在已存在的旧节点上立即判定成功。一次最终合格成片可有内部失败重试，失败原片与业务快照保留；只有测试夹具可以从已核验快照重新开局，真实用户数据不得倒退。

父固定`media_evidence.py`调用新版的原`video_evidence`计算核（本地仅增加FFmpeg线程上限），完整解码所有帧，5fps覆盖全时间线，接触页`frame_files`逐页有序一一对应全部采样原帧并核每个hash。首尾原帧、每个实际交互开始前0.2s/完成后0.2s、场景切换及疑点原帧单独提取并放大检查；全部交互原帧一次完整解码批量提取，仍每事件两张独立文件/哈希。首尾/交互截图也同查。独立ultra实际看完整接触页与必要原帧，核无白屏、加载遮挡、错对象、英文占满、数学推导和难读瞬间；抽样不能称看过全部原始帧。自动黑屏/冻结信号只是检查提示，正常静止阅读不直接判失败。record槽仅执行`--phase capture`，浏览器关闭后返回captured/passed=false，未写成功recording或成品；释放record后取得evidence单槽执行`--phase evidence`，编码、解码及完整证据结束才输出`.product-v2/controlled-video.json`和timeline，当前review绑定timeline hash；不是视觉通过。队列在整个重媒体阶段与所有live capture互斥，FFmpeg解码、滤镜及x264固定2线程。每次下载使用D盘唯一目录，不共享下载状态。

capture事实绑定原片hash、本案run、依赖、操作和实际服务身份；失败保留原片/observed事实，不当成功缓存。evidence失败可在同capture输入未变时继续，新独立证据目录保留失败历史，现有成片须属于同capture且hash一致才能续作；finalize仍强制完整decode/5fps/全部交互、当前review和收尾，不接受只有capture的原片。每案recording-stage.lock防止同案双写；异常退出遗留锁须核其PID身份确实退出并保存故障证据后由唯一父恢复，不能删除活跃锁。浏览器主线程rAF事实仅供性能诊断，不能代替源帧连续性及真实视觉检查，也不能据输出25fps就称不卡顿。

检查失败只修相关页面/计划，录制准备修复由ultra，父在录制槽重录并按当前依赖重新证据；首次已有合格一分钟不额外录短视频。ZIP说明专用修订只对同hashMP4补解码证据，不能借此重录。最终只向成品模拟系统复制当前合格演示视频.mp4，原片/失败证据完整内部保留。
