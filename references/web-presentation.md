# 页面质感与文案取舍

新建 Web 或用户明确要求界面改版时使用；完整业务链、真实视觉输入与原算法约束继续按 [Web设计](web-design.md) 执行。
目标是让用户更快找到对象、判断状态并完成操作。高级感来自合适的结构、准确内容和一致细节，不能靠装饰或删功能替代。

## 先定本案的短设计画像

在已有建设计划或简短设计画像中写清主对象、最常见任务、适合的阅读密度和视觉方向；数句足够，不另交报告或审批。
先确定主工作区放什么：影像、时间/空间、批次参数、排程占用或工作队列，再组织导航、辅助信息和操作。
例如影像检视优先原图与结果联动，调度优先任务与资源时段；不要把同一套指标卡换标题当作领域设计。
业务工作台保持可扫描、位置稳定；只有真实内容需要时才采用大幅引导区域，营销式 hero、巨标题和全屏装饰图不能挤占任务。
同领域可保留有效习惯，不同案件依对象与任务变化；不统一皮肤，也不为求不同破坏已有操作路径。

## 统一角色样式，不堆装饰

在本案已有样式变量或组件主题中统一背景、表面、正文、次要文字、边界、强调、状态等角色 token，避免逐页随意调色。
颜色服务业务语义：主操作有明确强调，状态同时有文字或图标，图中同一对象跨页同色；不能只凭红绿判断。
根据行业内容和中文可读性选字体，保留可用系统字体与合理回退；不机械禁用某种中文字体或配色，也不强制联网下载字体。
字阶应能区分页面标题、区域标题、正文与辅助信息；中文正文/控件可从 14–16px、行高 1.4–1.6 起步，再按实际密度调整。
紧凑表格可以更密，但对象名、结果、关键单位和风险不能压成小淡字；避免用过细字重或低对比度掩盖内容。
数值列按小数点或右侧对齐，适用时用等宽数字；统一精度、千分位、单位和时间格式，不改变技术含义或原计算精度。
正文与背景须清楚可辨，常规文字对比度以 4.5:1 为基准；次要文字只是层次较低，仍须在实际截图中可读。
间距用少量一致尺度，例如以 4/8px 递进；关联内容靠近，不相关区域留出分隔，不用巨大留白把表单和结果割裂。
先用对齐、间距、背景和轻边界分组；相邻内容不必逐项套卡片，避免卡片内再套卡片和所有区域同等强调。
圆角、阴影与渐变按需要少量使用；浮层可与页面拉开层级，普通表格不靠厚阴影，避免到处玻璃、渐变和巨大圆角。
同页同一数字或状态只在有决策价值的位置突出；全局摘要无需在每个功能页原样铺四张大卡。
密集业务保留合理紧凑的筛选、表格和详情区，分析/影像任务为主体视图留面积；不以统一大间距牺牲效率。

## 主视图与交互状态

图表与工具视图必须对应实际任务和数据：可定位对象、读出单位与阈值、比较结果，并执行原算法支持的筛选或检视。
图例、坐标、关键标记与选中状态清晰；必要详情可通过点击、悬停或展开查看，同时保留键盘或触控可达路径。
影像缩放/对照、时间窗、分区选择、排程冲突等依本案实际能力提供，不能为美观画无算法依据的框或固定结果。
选中对象、筛选、排序、页码及详情联动一致；局部操作保持用户位置，不能让刷新或迟到响应跳回旧对象。
默认、悬停、键盘焦点、选中、禁用、加载、成功、错误与空结果使用一致的组件规则，不只完成静态默认页。
按钮写明确动作，主次操作有区别；输入有可见标签与必要约束，图标按钮有可访问名称，焦点可见且不被浮层遮住。
处理中给出实际反馈并防止误触；失败说明对象、原因及下一步，保留已输入内容，不用一个“失败”迫使用户猜。
长名称、长数值、错误消息和中文换行不遮操作；截断后能查看完整内容，数值和单位不被无声裁切。
按实际使用窗口检查响应布局：主体操作、必要列和错误反馈可访问；确需横滚的业务表格有可理解的滚动区域。

## 文案：去除、按需展开、必须保留

先逐区判断文字是否帮助当前操作或判断，不能只凭字数删文案；按钮、标题、状态直接使用准确业务对象和动词。

| 处理 | 典型内容与落点 |
| --- | --- |
| 去除 | 制作过程、源码打包/录制/验收证明、自夸“真实可用”、页面实现说明、重复标题引导、与当前任务无关的原理长文 |
| 按需展开 | 确实影响当前判断的计算口径、字段含义、低频操作帮助；放在字段旁帮助、详情或帮助入口，默认不压住任务 |
| 必须保留 | 单位、阈值、输入范围/前置约束、重要风险与不确定性、权限或失败原因、未保存提示和可执行的错误恢复 |

内部制作说明应移出产品界面，仍在原内部证据中如实保留；把它搬进折叠框或问号提示不算精简完成。
用“批次记录”“处理结果”“待核对”等准确对象/状态替代制作话术；不得改称未经证实的实测、现场采集或生产运行。
“参数说明”“技术规则”“计算结果”“生成报告”等可服务业务，不一概删除；具体技术术语不能因高级感改错。
例如“请选择一个任务以开始使用本页面”可缩为“选择任务”；“上传失败：文件超过 20 MB，请压缩后重新上传”保留恢复路径。
影响安全、适用边界或结果解释的重要提示应在需要判断时可见，不能为了页面干净而藏入用户难以发现的位置。
这只约束 Web 可见文案，不削减 Word 正文解释、原文、原式或内部数据性质与来源证据。

## 在原检查中实看

沿原 high browser 自检和首次独立审查，查看全部业务页面及主要状态的当前实际截图，并结合真实操作判断。
在原浏览器日志/结论中简述实际发现和受影响项即可；不新增设计评分、强制报告、预检模型或第二套台账。
确认主对象与主操作一眼可定位，标题/数值/说明主次清楚；卡片和重复指标没有挤占有效内容。
实际阅读正文、辅助文字、图例、单位和长内容，核对比度、字阶、对齐和密度；截图缩略图或文件数量不能证明可读。
实际切到加载、空结果、错误、详情和选中等适用状态，核文字、布局、焦点与操作恢复；不以静态首页代替全部页。
逐区检查解释文字的去留：无用说明是否已删，必要帮助是否易找到，约束/风险/恢复是否仍在正确位置。
沿用 `auditUiText` 对当前可见文本查明确禁词；词表不判断所有冗长内容与高级感，零命中不等于视觉和文案通过。
主体能力、关键风险或恢复路径缺失应定向处理；纯风格偏好和无损功能的小瑕疵沿原收尾规则，不启动整案反复返修。
只更新受影响截图/检查与源码包；已合格且未受影响的 Word、数据和视频复用，冻结历史不因这份参考自动重做。
