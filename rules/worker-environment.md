# Worker 环境预检与停止条件

开始建设、返修或录制前，先确认自己案件工作区可正常读写：对本轮需要修改的现有业务文件用只打开不写字节的ReadWrite句柄检查访问，并确认本案输出目录可写；不要修改原件或用删除文件测试权限。若历史工程迁移过，优先核对web/scripts/evidence/exports。无关的Get-CimInstance拒绝不能等同于整个案件不可写，进程归属可结合启动记录、自己启动的PID和健康接口核对；不能因此停止其他程序。

如果业务目录的常规必要写入确实返回Access denied，停止该案制作，不反复换写法、不更改ACL/沙箱/安全规则。将实际失败命令与错误记入根目录 .caseflow-environment.json：{"status":"blocked","requires_environment_repair":true,"reason":"具体目录、实际命令和错误"}。evidence不可写时仍使用根目录；根目录也不可写时，最终回复独立一行 `CASEFLOW_ENVIRONMENT_BLOCKER:{"status":"blocked","requires_environment_repair":true,"reason":"具体证据"}`。该结构会让父执行器仅阻断本案，保留进度并继续其他案件，避免空转付费返修。

正常预检通过或环境修复后，写入 .caseflow-environment.json：{"status":"ready","requires_environment_repair":false,"reason":"实际检查范围"}，再继续原任务。不要将普通代码、图表、排版缺陷当作环境问题；这些问题仍应修到通过。单条命令的blocked by policy是独立策略拒绝，不能说成Windows ACL故障，也不能改写命令、换进程或改权限绕过该拒绝；记录具体受限动作并使用任务范围内合法替代步骤。

## 本案服务的非交互启停（2026-09-28）

录制或返修前，先查已分配端口和健康接口。服务的案件标识、工作区、代码/计算版本与当前成果一致时复用，不为每个阶段另起一份；版本过旧才维护。启停授权限于当前用户已要求处理的案件，维护前保全数据库与原状态。

停止前同时核对监听端口、PID、进程创建时间、命令行，以及健康接口中的案件标识/工作区；执行前再核对PID身份，禁止按python/node等通用名称批量停止或顺带停止未核实的父进程。非交互工具里使用标准 `Stop-Process -Id <已核实的本案PID> -Force -ErrorAction Stop`，其中 `-Force` 仅省去进程停止确认，不提升权限；用户已授权本案维护时无需再弹一次确认。停止后核验监听消失，未退出不记成功。若普通 `Stop-Process` 出现空引用，保留完整异常栈；栈位于 `ConsoleHostUserInterface.PromptForChoice` / `ShouldContinue` 表示确认提示失败，不能把它写成ACL或策略拒绝。实际Access denied或工具明确blocked by policy仍按前述阻塞规则处理，不以免交互参数掩盖或绕过拒绝。

启动使用已核实的运行时、案件目录和空闲的已分配端口，标准 `Start-Process` 必带 `-WindowStyle Hidden`、`-PassThru` 及各案独立的stdout/stderr日志；记录launcher PID及实际listener PID，二者可能不同。启动命令返回或进程存在不算恢复：健康接口必须返回当前案件与版本，首页和关键业务API需实际响应。服务恢复后由父执行器保留旧阻塞证据、调用历史和录制待办，继续未完成案；新版计算记录尚空时先经真实后端产生结果。不得用健康检查替代浏览器/Word/新视频及独立验收，也不得复用版本不符的旧证据。

本次依据：`evidence/service-recovery-20260928-090728/stop-process-error.txt` 与 `recovery-report.json`；标准参数说明：[Microsoft Stop-Process](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/stop-process?view=powershell-7.5)。

## 运行环境与停服前置检查（2026-09-28 故障修复）

- `ModuleNotFoundError` 是依赖/解释器选择错误，不是权限不足。必须保留实际可用的虚拟环境启动器；venv 的监听子进程可能显示基础 uv Python，不能把该子进程路径直接替换启动器。先用拟使用的启动器真实导入本案依赖，记录启动器路径、sys.executable、sys.prefix、sys.base_prefix及包版本；失败时修正本案运行环境，不改整个机器的权限或批次全局运行时。测试仍按项目既定bundled Python约定；需项目依赖的服务使用已核验的案件环境。
- Windows PowerShell 5.1 用户脚本含中文时保存UTF-8 BOM，读UTF-8 JSON显式指定编码。在实际5.1解析之外，还要用脚本中的准确Python启动器做真实依赖检查；仅语法通过不能写“可启动”。PowerShell5.1调用含引号的Python代码时，优先使用独立.py文件并通过真实5.1进程运行该预检，避免只在新版shell验证-c字符串。启动脚本显示进度，子进程已退出即读独立stderr并停止无效健康轮询。
- 同一案件已出现服务启动 `blocked by policy` 且没有外部解除证据时，worker禁止停止仍健康的本案服务，包括为了重启读回、换计算版本或清理阶段；先完成可做的代码/离线自检与证据准备，保留服务，记录在线版本与磁盘版本差异。需要合法维护时交由单一负责人协调，不能先停再发现启动受限，更不能换工具、命令包装、进程或安全配置绕过原拒绝。保留旧服务不代表可把旧证据当成当前版验收。
- 单个录制或验收阶段结束、但最终验收交付尚未完成时不关闭服务；最终交付完成后的回收按下节执行。必须维护时，先完成当前版本代码/依赖/入口/端口/数据备份检查及明确恢复安排，再核实归属；不能把端口空闲或解析成功当作服务启动已获准。已停且启动被拒的案件只在用户实际启动或外部条件变化并经健康身份/版本核实后恢复付费阶段，其他案件继续。
- 错误分开记录：工具执行前拒绝、Windows必要写入拒绝、文件占用、依赖导入失败、服务运行时异常、健康版本不符。当前任务的可写句柄测试只证明当前任务权限，不能替另一worker沙箱声明可写；不修改ACL、安全Deny、sandbox或审批策略来消除报错。
- 媒体依赖由总控统一维护，优先使用config.json指向的项目运行资源目录中的正常工具包。WinGet应用目录中的工具不可读/执行失败，不等于案件业务目录不可写；保留原始录制和健康服务，将具体工具路径、CreateProcess错误交给总控。总控可核验已合法安装的独立媒体依赖、保留来源/许可证/哈希并更新后续配置，不复制受限文件或更改安全规则。新工具必须实际完成版本检查、编码、探测和解码；父层验证不能替代worker自身首次执行结果。旧父执行器仍可持有旧runtime缓存，后续必要阶段显式传入新路径，不为刷新配置中断正常批次。


## 交付后后台回收（2026-09-29用户要求）

- 触发点是本案按当前用户授权交付范围完成最终独立验收、成品落盘及当前文件哈希核验；worker退出、一次录制结束、健康检查通过或历史pass均不能代替交付。由原批次负责人在本案收尾时及时处理，不等全批结束，不为此定时巡检或暂停/重启父执行器。
- 先核实state、控制请求、末尾阶段日志及实时进程，确认没有在途建设/返修/录制/验收、待办返修或用户要求保留在线。正在执行和正常排队均不属于可回收。
- 对服务核对案件ID、工作区、端口、PID、创建时间、命令行及健康身份/版本；对专属浏览器、CLI、辅助进程用本案启动记录、独立配置目录和实时身份核对。共享进程、有其他使用者或归属不明时保留，不猜测。动作前再次核实身份以防PID复用。
- 先使用本案已有正常退出方式；必要时精确停止已核实的本案PID，只处理已无工作的专属后台。禁止按进程通用名称批量停止、盲目结束父进程或进程树。仍有未完成案的批次父执行器、拟名称服务（PatentTitleBot及Hermes依赖）、其他项目和用户大型应用不在回收范围。
- 验证目标进程退出、相应监听释放；保留回收前后进程身份、原因、停止结果及提交内存变化到本批维护证据，不把物理空闲内存或缓存回收当作释放提交额度。不删除/改写源码、数据库、原件、成品、证据或调用计数。必要的运行时落盘按正常退出流程完成，交付哈希保持不变。
- 若仍有业务依赖、无法证明归属或停止被拒，保留进程并记录具体原因；策略拒绝、ACL、占用、OOM分别记录，不换命令/工具或改安全设置绕过拒绝。回收失败不伪造已释放，也不否定已完成交付。后续用户再要求在线或返修时，按正常归属及环境预检恢复服务，不自动重启已回收服务。
