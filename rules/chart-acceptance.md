# 从用户实际改图中提取的验收标准

2026-09-23追加。已读取当日11个建设任务的最新用户消息与最终回复，原文存于 `evidence/current-chart-records.json`。41张当时文件快照及SHA256见 `evidence/chart-learning/latest.json`；文件仍可能在原任务继续变化。这里只修改自动化规则，不修改其他任务的代码、图件或进程。

## 用户实际要求

1. **看得懂比“已经出图”更重要。** 读者应直接辨认横纵轴、系列、业务含义和变化。用户在压延垫布、现场总线任务明确说“看不懂”，说明有线有点不算通过。难懂的图先改图形表达和短业务标签，不能靠加一大块解释框补救。
2. **文字要大、深、在成品尺寸可读。** 加热、轮胎APC、道路诊断任务反复指出文字太小、太淡。检查原PNG、网页正常显示宽度及Word实际插入宽度；只放大图片查看不能证明达标。字体数值按具体图幅调整，不把某个统一字号当万能通行证。黑/深灰文字为主，淡灰留给次要网格。
3. **图例在绘图区留白处，所有系列都有归属。** 图例不能压线、柱、点或数值标注；也不能缩小到看不清。检查每个子图，而非只检查第一个。道路诊断最新要求是“最后两个图的图例不完整”，所以单系列面板也不能盲目省掉必要说明；只有轴/直接标签已经无歧义时才可省略重复图例。
4. **图例短而专业，不装说明段落。** 不要“参考”“本地”、冗余括号、长句、“按各自量纲”或内部追踪术语。例如“下界”“上界”“发车门槛”“目标值”比长句更合适。标签依本案定义命名，不能仅把专业词换成“A/B”而让语义丢失。重合原因、计算条件写进详细说明，来源与数据性质集中保留README；应披露的事实仍保留。说明篇幅按2026-09-24新规则展开，不再限300–400字。
5. **图内无表头、左下角小字和额外说明框。** 用户提供的反例包括“三分区结果重合／均达到本轮搜索窗口上限”、一大块“从左向右…来源切换…”解释框，以及“本地与参考首分量（一致）”式冗余图例。普通坐标单位与必要数据标签保留，说明移到图外对应正文。
6. **数据充分，曲线完整，同时避免拥挤。** 加热任务不接受大量曲线挤作一团；光伏任务明确“每一个保留一两个典例”。默认按一两个有代表性的工况/对象组织视图，完整数据保留CSV；一个典例所需的多条物理量、边界、阈值仍须完整呈现，不机械限定为两条线。不为简洁漏掉必要图例。
7. **补数据必须补进系统并重算。** 压延垫布、双气囊、轮胎、化妆品、公交V2G、光伏都被要求补足数据。应补合理工况、完整周期、事件前后、约束边界、有效业务记录，再按源式由后端重算，更新同一快照的PNG/CSV。不能只给图片加点、随意拉长线、重复行凑数或插值填真实缺测。真实缺口保持断点并在说明解释。
8. **“没画完”是要检查的数据与显示问题。** 检查时间终点、工况覆盖、横轴范围、缺失原因及导出裁切。公交V2G的例子要求延续到实际发车边界；具体端点随案件定义，不能把它复制到其他领域。源规则是常值或离散状态时如实画常值/阶梯，不为丰富视觉捏造起伏。
9. **黑白中也能区分线。** 使用有差异的实线/虚线/点划线、空心/实心标记与可见灰阶，图例必须同步。数值真实重合时不能人为偏移伪装差异；可用错开的标记采样位置、合适分面或在说明解释共享轨迹。图例中的冗余括号说明仍应清理。
10. **图数与公式数分开，每案至少两张有意义的图。** 用户2026-09-24明确修正：一个公式可多图、也可不单独出图，多个公式可支撑同一图；没有独立公式也要有至少两张有依据的业务结果图。先确定业务问题与证据再选图。公式审计仍完整，不能以多个子图、多种序列或行内变量冒充更多源公式。旧“图数由公式组决定”的约束撤销。

同时执行[图表质量关卡](chart-quality.md)和[材料补充流程](material-sourcing.md)。用户否定的四张截图已作为反例保全：贫乏真假值条形、保留/重算卡片、圆点真值表、大色块条件表不计为合格交付图。昨天五案的旧独立验收者通过不代表用户接受，返修必须重新选题和审查。先判断图值不值得画，再检查样式；不能只移动图例、加大字体后原样返还。

## 如何判“过关”

后续新批次另执行[2026-09-28专业图表补充](chart-professional.md)：新增结果图采用专业数据图表，不插示意图；有公式关联的解释尽量自然使用原公式关键符号。严格依[批次范围](chart-professional-scope.json)应用，既有批次不因本条返修或重验。

依次判断：源公式/数据正确 → 图形能解释业务 → 数据范围充分 → 每个系列与图例对应 → 图内标签简洁 → 文字/线清楚 → 没有遮挡或裁切 → 页面PNG与Word插图是同一最终版本。任何硬错误返回具体文件和区域的返修意见；不能靠平均评分抵消遗漏。

用户让“插入Word”、打开web或停止项目，说明流程已向后推进，可把此前版本列为**候选参考**；这些话并不等于明确认可所有细节，更不等于后续仍在修改的文件已经通过。只有用户明确认可具体版本，或当前独立验收者按完整规则实际验收并记录哈希，才标记对应版本通过。必须区分用户认可、独立验收者验收、仅助手自称已修、仍待修改。

对当前41张快照不批量签通过。本轮另看了3张用户裁剪反例及4张原PNG：压延垫布第2图可参考分段标记与深色文字；公交V2G能参考完整时间终点，但图例仍在外侧，不能作为全部规则合格样本；光伏第2图可见稀疏/断续数据和长括号图例，应作为返修例；道路第4图当前快照已经有分面图例，但仍无用户对该哈希的明确认可。
